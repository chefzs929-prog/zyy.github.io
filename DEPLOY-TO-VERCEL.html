Vercel 迁移手册

目标：微信里能直接打开 · 首屏更快 · 反馈与分享数据安全留存

先说清楚一件事：这不是「换个地方放文件」那么简单。现在的反馈功能接在 WorkBuddy 云端数据库上， 而那个 API 就挂在 zyy.app.workbuddy.host —— 正是屏蔽微信的那个域名。 实测从 https://zyy.vercel.app 跨域调用它返回 403， 并且不返回任何 access-control-allow-origin。 所以搬到 Vercel 后，现有反馈功能必然失效，必须给它配一个新数据库。这正是下面要做的事。

方案速览

环节用什么为什么选它
托管 Vercel · 免费 全球 CDN、自动 HTTPS、导入 GitHub 仓库即可。不做 UA 拦截，微信能打开
数据库 Supabase Postgres · 免费 500MB 自带 REST 接口，直接用 fetch 调、不用装 SDK，首屏零负担。自带网页后台可直接看表
权限 行级安全 + 口令读函数 权限放在数据库里，不在前端。任何人读不到、改不了、删不了
查看 网页后台 / 导出 CSV / 邮件推送 三种方式任选，互不冲突
关于那串公开 key：需要把 Supabase 的公开 key 写在网页代码里，它会出现在访客浏览器中。 这是 Supabase 的既定设计 —— 这串 key 本身没有任何读权限，真正拦住读操作的是数据库的权限策略。 就像大门地址公开、钥匙在你手上。

第 1 步：准备 Supabase 数据库

1
注册并建项目 打开 supabase.com，用 GitHub 登录 → New project。 Region 建议选 Singapore（离国内最近、延迟最低）。Region 一旦选定无法更改，别选错。 记下建库密码，丢了也可以重置。
2
记下两串值 左侧 Project Settings → API：Project URL（形如 https://abcd.supabase.co） 与 anon public key（一长串）。这两串稍后要填进网页。
3
建表 左侧 SQL Editor → New query，粘贴执行。反馈表刻意不设 owner_id —— 匿名访客没有登录身份，那个字段一旦 NOT NULL 就会插入失败。 
-- 反馈表
CREATE TABLE feedbacks (
  id         BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name       TEXT NOT NULL CHECK (length(name) <= 40 AND length(btrim(name)) > 0),
  rating     INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
  comment    TEXT NOT NULL CHECK (length(comment) <= 1000),
  profession TEXT,
  device     TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 分享推荐表
CREATE TABLE recos (
  id         BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kind       TEXT NOT NULL CHECK (length(kind) <= 20 AND length(btrim(kind)) > 0),
  content    TEXT NOT NULL CHECK (length(content) <= 500 AND length(btrim(content)) > 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
4
锁权限（整个方案的安全核心） 开启行级安全后，只建 INSERT 策略、只授权 INSERT。没有 SELECT 策略，任何客户端读不到； 没有 UPDATE / DELETE，改不了删不了。自增序列的 USAGE 必须补，否则 id 自增会报权限错。 
-- 反馈表：只允许写入
ALTER TABLE feedbacks ENABLE ROW LEVEL SECURITY;
GRANT INSERT ON public.feedbacks TO anon, authenticated;
CREATE POLICY feedbacks_insert_only ON feedbacks
  FOR INSERT TO anon, authenticated WITH CHECK (true);

-- 分享表：同样处理
ALTER TABLE recos ENABLE ROW LEVEL SECURITY;
GRANT INSERT ON public.recos TO anon, authenticated;
CREATE POLICY recos_insert_only ON recos
  FOR INSERT TO anon, authenticated WITH CHECK (true);

-- 自增序列授权，缺了会插不进去
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO anon, authenticated;

第 2 步：部署到 Vercel

1
把代码传到 GitHub 在 GitHub 上 New repository（建议选 Private，网页里会带 key），然后在项目目录执行： 
git remote add origin git@github.com:你的用户名/仓库名.git
git branch -M main
git push -u origin main
2
导入到 Vercel 打开 vercel.com，用 GitHub 登录 → Add New → Project → 选中仓库 → Import。 Framework 选 Other，Build Command 留空，Output Directory 留空，点 Deploy。 几十秒后拿到 https://项目名.vercel.app。
3
在微信里验证 用蜂窝网络（别连 WiFi）把链接发到微信里点开，页面应该正常出现。 如果还打不开，那是 Vercel 部署或域名还没生效，不是代码问题。
先用免费的 vercel.app 子域名跑通全流程，确认没问题后再买自己的域名。 买好后在 Vercel 项目 Settings → Domains 里添加，按提示去注册商加一条 CNAME 即可，不用备案。

第 3 步：让首页加载更快

现在的瓶颈不在网络，在体积。3D 那一套加起来超过 1MB，而且目前是同步阻塞的：

资源体积处理方式
three.module.min.js656 KB改成动态 import，不再阻塞首屏
fz.glb 模型216 KB同上，渲染空闲后再加载
GLTFLoader 等 addons200 KB同上
workbuddy-cloud-sdk60 KB整个删掉，改用原生 fetch 调 REST
canvas-confetti12 KB加 defer，最后加载
字体76 KB已是 swap 模式，不阻塞
这样一轮下来，关键路径从约 1.2MB 降到约 226KB（HTML + CSS + 字体）。 3D 模型在文字内容显示完之后才开始下载，中间由现在的占位剪影顶着 —— 访客先看到内容，机器人稍后登场。

第 4 步：三种查看数据的方式

方式一 · 网页后台（推荐，手感与现在一致）

沿用现在的 ?admin=1 隐藏入口加口令，只是底层换成 fetch。 口令以哈希形式存在数据库里，读错直接返回错误码，一行数据都拿不到。

-- 口令表：开启 RLS，但零授权零策略，客户端完全不可读
CREATE TABLE admin_secret (k TEXT PRIMARY KEY, pass_hash TEXT NOT NULL);
INSERT INTO admin_secret VALUES ('owner', md5('wbfb::' || '你的口令'));
ALTER TABLE admin_secret ENABLE ROW LEVEL SECURITY;

-- 读函数：SECURITY DEFINER 绕过 RLS，口令不符直接抛错
CREATE OR REPLACE FUNCTION read_feedbacks(pass TEXT)
RETURNS SETOF feedbacks LANGUAGE plpgsql
SECURITY DEFINER SET search_path = public AS $fn$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM admin_secret
                 WHERE k='owner' AND pass_hash = md5('wbfb::' || COALESCE(pass,'')))
  THEN RAISE EXCEPTION 'BAD_PASS' USING ERRCODE = '42501'; END IF;
  RETURN QUERY SELECT * FROM feedbacks ORDER BY created_at DESC;
END; $fn$;

GRANT EXECUTE ON FUNCTION read_feedbacks(TEXT) TO anon, authenticated;
md5() 是 Postgres 内置函数，不用装插件。把「你的口令」换成自己定的。
对照 recos 表可以照写一个 read_recos(pass)，逻辑完全相同。

方式二 · 邮件自动推送

你日常就在用 QQ 邮箱。可以让我写个定时任务，每天固定时间把新增反馈汇总成一封邮件发给你， 不用惦记着去后台看。这个等上面跑通了再说。

方式三 · 直接在数据库后台查看或导出

Supabase 网页端 Table Editor 可以直接浏览表格，右上角 Export → CSV 一键导出。 这个是白送的，不用写任何代码。

投产前验收清单

  • 用微信（蜂窝网络）打开站点 —— 页面正常显示
  • 随便提交一条反馈 —— 提示成功，且 Supabase 表里真的多了一行
  • 用错误口令进 ?admin=1 —— 报错，拿不到任何数据
  • 用正确口令进去 —— 能看到刚才那条真实反馈
  • 没有口令时直接访问读取接口 —— 应被拒绝
最后一件事：本地 file:// 或 localhost 预览时提交会失败，因为数据库只放行配置好的正式域名。 这是正常的，不是功能坏了 —— 必须在 Vercel 上线后的域名上测。
